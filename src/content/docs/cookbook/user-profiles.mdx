In this tutorial, you will learn how to create an Arkiv entity to store a user's profile information.

You will learn what to store in the entity's **attributes** vs in the entity's **payload**.

| Field Type     | Description               | What we will store                     |
|----------------|---------------------------|-----------------------------------------|
| [**Attributes**](/start-here/fundamentals/#entities) | queryable filters         | user’s handle and wallet address        |
| [**Payload**](/start-here/fundamentals/#entities)    | free-form fields          | user’s display name and bio    |

## Prerequisites

- [`@arkiv-network/sdk`](https://www.npmjs.com/package/@arkiv-network/sdk) installed
- [`viem`](https://www.npmjs.com/package/viem) installed
- a wallet funded with testnet tokens from the [faucet](/networks/tiramisu/)

```bash
npm install @arkiv-network/sdk viem
```

## Create a user profile

<Steps>

1. **Set up the clients**

   We will first setup two clients:
    - one `publicClient` for read-only queries
    - one `walletClient` for write operations
  
   The `PROJECT` constant below scopes every entity you will create to your app. Since Arkiv is a shared public database, this is to prevent queries from returning other projects' profiles, if these projects use the same entity structure.

   ```ts title="arkiv.ts"
   import { createPublicClient, createWalletClient } from "@arkiv-network/sdk"
   import { tiramisu } from "@arkiv-network/sdk/chains"
   import { http } from "viem"
   import { privateKeyToAccount } from "viem/accounts"

   // Replace with a globally unique string for your own app
   export const PROJECT_ID = "your-app-project-id" as const

   export const publicClient = createPublicClient({
     chain: tiramisu,
     transport: http(),
   })

   export const walletClient = createWalletClient({
     chain: tiramisu,
     transport: http(),
     account: privateKeyToAccount(process.env.PRIVATE_KEY as `0x${string}`),
   })
   ```

   <Aside type="caution">Always ensure to store sensitive informations - such as private key in this example - in environment variables.</Aside>

2. **Define the profile shape**

   ```ts
   type Profile = {
     handle: string      // attribute: unique, used for lookups
     wallet: string      // attribute: used for lookups
     displayName: string // payload
     bio: string         // payload
   }
   ```

3. **Create a profile**

   ```ts title="create-profile.ts"
   import { ExpirationTime, jsonToPayload } from "@arkiv-network/sdk"
   import { PROJECT_ID, walletClient } from "./arkiv"
   
   type Profile = {
     handle: string      // attribute: unique, used for lookups
     wallet: string      // attribute: used for lookups
     displayName: string // payload
     bio: string         // payload
   }

   export async function createProfile(profile: Profile) {
     const { entityKey } = await walletClient.createEntity({
       contentType: "application/json",
       attributes: {
         projectId: PROJECT_ID,
         entityType: "profile",
         handle: profile.handle,
         wallet: profile.wallet,
         updated: Math.floor(Date.now() / 1000),
       },
       payload: jsonToPayload({
         displayName: profile.displayName,
         bio: profile.bio,
       })
     })

     return entityKey
   }

    const profileEntityKey = await createProfile({
     handle: "ada",
     wallet: "0x1111111111111111111111111111111111111111",
     displayName: "Ada Lovelace",
     bio: "Writes notes on engines.",
   });

   console.log("User profile created successfully! Profile entity key:", profileEntityKey);
   ```

   In the code example above, we are saving a new profile info to Arkiv using the [`createEntity`](/typescript-sdk/api-reference/main/functions/createwalletclient/#createentity) function from the Arkiv SDK

   When creating this entity for a user profile, we are storing the user profile and app information in different places within the entity.

   We are storing in the **attributes**:
   - the user's handle: _so we can look up this specific profile by its handle_
   - the user's wallet address: _so we can look up this specific profile by its wallet address_
   - the project id: _so we can query all profiles for this specific app_

   We are storing in the **payload** the remaining generic user information:
   - the user's display name
   - the user's bio

   <Aside>
   `updated` is stored in **seconds**, not milliseconds. A bare number becomes an `i32`, and a millisecond timestamp overflows that range. Seconds fit, and stay comparable with `gt()` and `lt()`.
   </Aside>

</Steps>

## Query examples

Below are some examples of how to query user profiles and use Arkiv filtering capabilities.

<Aside type="tip">
See more advanced examples for the [`select()`](/typescript-sdk/api-reference/main/type-aliases/publicarkivactions/#select) function to see how to retrieve only specific fields from the entity.
</Aside>

### Look up a profile by handle or address

   ```ts title="search-profile.ts"
   import { eq } from "@arkiv-network/sdk/query"
   import { PROJECT, publicClient } from "./arkiv"

   export async function getProfile(handle: string) {
     const { entities } = await publicClient
       .select("*")
       .where(
         eq(PROJECT.key, PROJECT.value),
         eq("entityType", "profile"),
         eq("handle", handle),
       )
       .limit(1)
       .fetch()

     const entity = entities[0]
     if (!entity) return null

     return {
       key: entity.key,
       handle,
       wallet: String(entity.attributes.wallet?.value),
       ...entity.toJson(),
     }
   }
   ```

   Swap `eq("handle", handle)` for `eq("wallet", address)` to look the same profile up by wallet address instead.

   <Aside type="tip">
   You can also specify what you want to retrieve from the `select()` function. For instance:
   
   if you want to retrieve only the user's attributes 
   

   ```ts
   select({ attributes: true })
   ```

   or only the user's keys.

   ```ts
   select({ key: true })
   ```
   </Aside> 

### Search profiles starting with a specific handle prefix

String attributes support prefix matching. You can also use `limit(number)` to limit the number of results you want to get returned.

```ts title="search-profile.ts"
import { eq, startsWith } from "@arkiv-network/sdk/query"

const { entities: results } = await publicClient
  .select({ key: true, payload: true, attributes: true })
  .where(
    eq("projectId", "<your-app-project-id>"), // Replace with your app's project id
    eq("entityType", "profile"),
    startsWith("handle", "ad"),
  )
  .limit(20)
  .fetch()

console.log("Entity search results:", results);
```

### Get all profiles handles

```ts title="get-all-profile-handles.ts"
import { eq, startsWith } from "@arkiv-network/sdk/query"

const { entities: allProfileEntities } = await publicClient
  .select("*")
  .where(
    eq("projectId", "<your-app-project-id>"),
  )
  .limit(20)
  .fetch()

console.log("All profile entities result:", allProfileEntities);
```

### Get all profiles for this app

String attributes support prefix matching. You can also use `limit(number)` to limit the number of results you want to get returned.

```ts title="get-all-profiles.ts"
import { eq, startsWith } from "@arkiv-network/sdk/query"

const { entities: allProfileEntities } = await publicClient
  .select("*")
  .where(
    eq("projectId", "<your-app-project-id>"), // Replace with your app's project id
  )
  .limit(100) // Limit to 100 results if you want to do pagination
  .fetch()

console.log("All profile entities result:", allProfileEntities);
```

<Aside type="caution">
Handle uniqueness is your app's job. Arkiv does not enforce it. Check with `getProfile()` before creating, and treat the query as advisory since another writer can create the same handle in between.
</Aside>


## Update a profile

   Use the [`patchEntity`](/typescript-sdk/api-reference/main/functions/createwalletclient/#patchentity) function from the Arkiv SDK to update an entity.
   
   You can specify only the fields or attributes you want to update. Fields you do not name keep their current value (so you never have to read the profile first)

   ```ts title="update-profile.ts"
   import { jsonToPayload } from "@arkiv-network/sdk"
   import { walletClient } from "./arkiv"
   import { getProfile } from "./get-profile"

   const profile = await getProfile("ada")
   if (!profile) throw new Error(`No entity found for profile handle "ada"`)

   // Update Ada's wallet address
   const newWalletAddress = "0x1010101010101010101010101010101010101010"

  // Update the payload but keep the current displayed name
  const { displayName } = profile;
  const updatedBio = "Born in 1815, Ada Lovelace is considered to be the first computer programmer."

  await walletClient.patchEntity({
    entityKey: profile.key,
    payload: jsonToPayload({ displayName, bio: updatedBio }),
    contentType: "application/json",
    set: { updated: Math.floor(Date.now() / 1000), wallet: newWalletAddress },
  })
  ```

   <Aside>
   The payload is replaced whole, not merged. Attributes are merged. That is why `displayName` is passed through here while the attributes you do not name stay untouched.
   </Aside>
