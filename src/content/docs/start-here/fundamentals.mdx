Arkiv is a universal data layer that brings queryable, time-scoped storage to Ethereum. Store, query, and manage data with built-in expiration and attribute systems.

## Reasons to use Arkiv

<Card title="Indexed Queries" icon="magnifier">
  You can run SQL-like queries on attributes. The data has an index, so you do not need an external indexer.
</Card>
<Card title="Cost-Efficient" icon="approve-check-circle">
  You pay only for the storage duration you choose. Arkiv prunes data automatically, so there are no permanent storage fees.
</Card>
<Card title="Ethereum-Native" icon="star">
  Arkiv is built on Ethereum infrastructure. It is transparent, tamper-evident, and it works with existing Web3 tools.
</Card>
<Card title="Developer-Friendly" icon="pencil">
  Arkiv gives you simple CRUD operations and a TypeScript SDK with full type safety.
</Card>

## Architecture

Arkiv is designed as three layers:

```
┌─────────────────────────────────────────────────────┐
│  YOUR APP                                           │
│  TypeScript SDK  ·  JSON-RPC                        │
└────────────────────────┬────────────────────────────┘
                         │  read / write
                         ▼
┌─────────────────────────────────────────────────────┐
│  LAYER 3 : DB-CHAINS                                │
│  Convenient CRUD, indexed queries,                  │
│  programmable expiration                            │
└────────────────────────┬────────────────────────────┘
                         │  coordination
                         ▼
┌─────────────────────────────────────────────────────┐
│  LAYER 2 : ARKIV COORDINATION LAYER                 │
│  DB-chain registry,                                 │
│  deterministic query resolution                     │
└────────────────────────┬────────────────────────────┘
                         │  settlement
                         ▼
┌─────────────────────────────────────────────────────┐
│  LAYER 1 : ETHEREUM MAINNET                         │
│  Proof verification, commitments,                   │
│  ultimate source of truth                           │
└─────────────────────────────────────────────────────┘
```

## Core Concepts

### Entities

An entity is a data record on Arkiv. Every entity contains:

- **Payload**: The actual data (JSON, text, binary)
- **Attributes**: Typed key-value pairs for querying
- **Expiration date**: Every entity expires automatically. Set it when you create the entity.
- **Content Type**: MIME type of the payload

### Attributes

Attributes are an object keyed by name. The type you give a value determines what query operators are available. Typed helpers (`str`, `i32`, `u64`, `u256`, `dec`, `bool`, `addr`, `key`, `bytes32`) come from `@arkiv-network/sdk/attr`. You do not need a helper for a plain string value:

```ts
import { i32 } from "@arkiv-network/sdk/attr";

// String attributes: support eq() and startsWith() prefix matching
{ type: "note" }
{ status: "active" }

// Numeric attributes: i32, u64, u256 and dec support range queries (gt, lt, gte, lte)
{ priority: i32(5) }
```

<Aside type="caution">
If you write a number as a `str` instead of a numeric type, you cannot do range queries. `gt()`, `lt()`, `gte()` and `lte()` stop working. Use a numeric helper for a value you plan to filter by range.
</Aside>

<Aside type="caution">
`i32` values must be **integers**: a float like `1.5` throws an `InvalidValueError`. For non-integer values, use `dec()` instead. It stores fixed-point decimals, for example `dec("1.5")`.
</Aside>

### Expiration

Every entity has a lifespan. Use the `ExpirationTime` helper to set one:

```ts
import { ExpirationTime } from "@arkiv-network/sdk";

ExpirationTime.fromMinutes(30)
ExpirationTime.fromHours(12)
ExpirationTime.fromDays(7)
ExpirationTime.atBlock(1_200_000n)
ExpirationTime.atDate(new Date("2027-01-01"))
ExpirationTime.permanent()
```

Pass the result as `expires` on `createEntity()` or `extendEntity()`.

<Aside>
You can extend an entity before it expires with `extendEntity()`. Start with a short expiration to save on storage fees. If you need more time, extend it later.
</Aside>

### Query Language

A query is a boolean expression, with no `SELECT` and no `WHERE`. Keywords are case-insensitive:

```sql
type = str('note') AND priority > i32(3)
```

Supported operators: `AND`, `OR`, `NOT`, `=`, `<`, `>`, `<=`, `>=`, `STARTSWITH` (string prefix match). A bare boolean is untagged (`true`/`false`) and a bare number defaults to `i32`. Every other value needs its type tag, for example `str('open')` and `u64(1200000)`. Use `*` to match every entity.

`!=` is not supported by the query language yet. Write `NOT (attr = value)` for the complement instead.

Full syntax reference: [Query syntax](/json-rpc/querying-data/#query-syntax).

### Clients

Two client types exist:

- **WalletClient** (read/write): Needs a private key or a wallet connection. Use it to create, patch, and delete entities.
- **PublicClient** (read-only): Needs no private key. Use it for queries. It is safe for frontend use.

## What You Can Query

The query builder of the SDK does more than basic filtering. Before you write a manual workaround, see what it already provides:

- **Field selection**: You fetch only the entity fields you need with `select({ key: true, payload: true })`. The result type narrows to exactly those fields.
- **Newest-first results**: Matching entities always come back newest first. To sort them differently, sort the results in JavaScript.
- **Pagination**: You can page through results with `hasNextPage()` and `next()`. Each page holds up to 200 results.
- **Entity count**: You can get a count without fetching entities. Call `getEntityCount()`.
- **Owner and creator filters**: Use `.ownedBy()` and `.createdBy()` to filter by wallet.

Full reference: [Querying Data](/typescript-sdk/querying-data/)

## Use Cases

- **Temporary Data Storage**: Session data with automatic expiration, cross-device clipboards, cached API responses.
- **Event & Analytics**: Application logs with cleanup, user activity tracking, temporary metrics.
- **File & Media**: Image metadata with expiration, document versioning, chunked file storage.
- **Full-Stack Applications**: Dashboards, collaborative tools, browser-based dApps with wallet signing.
