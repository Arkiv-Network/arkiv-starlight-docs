---
title: Paginate results
description: Read query results a page at a time, walk every page with for await, resume from a cursor, and read the chain as of a past block.
---

A query returns its results in pages of up to 100 rows. You can fetch them one page at a time, or walk every row with `for await`. The examples on this page use the `Posts` schema and clients from [your first entity](/start-here/first-entity/).

## Fetch one page at a time

`limit` sets the page size, and `fetch` returns the first page. `next` fetches the page after it:

```ts
import { eq } from "@arkiv-network/sdk/query"

const page = await publicClient
  .select({ $key: true, title: true })
  .from(Posts)
  .where(eq("category", "news"))
  .limit(50)
  .fetch()

if (page.hasNextPage()) {
  const nextPage = await page.next()
}
```

Without `limit`, the node chooses the page size. A page holds:

- **`entities`**: the rows on this page
- **`cursor`**: where the next page starts, or `undefined` on the last page
- **`blockNumber`**: the block the page was read at
- **`skipped`**: how many entities were left out because they [don’t fit the schema](/querying/select/#entities-that-dont-fit-the-schema)
- **`count`**: how many entities the query matches in all, if you [asked for it](/querying/count/#count-alongside-a-page)

Every page of one query reads the same block, so rows don’t shift between pages while you read.

## Walk every row

A query is async iterable. `for await` fetches pages as it needs them:

```ts
const news = publicClient
  .select({ $key: true, title: true })
  .from(Posts)
  .where(eq("category", "news"))

for await (const post of news) {
  console.log(post.$key, post.title.value)
}
```

## Resume from a cursor

To continue in another request, for example when a user clicks **Load more**, save the page’s `cursor` and pass it to the same query later:

```ts
const more = await publicClient
  .select({ $key: true, title: true })
  .from(Posts)
  .where(eq("category", "news"))
  .limit(50)
  .cursor(savedCursor)
  .fetch()
```

A cursor only works with a query built the same way, with the same selection and filters. Cursors expire. An expired one fails with a `QueryError` whose `kind` is `"cursor"`: start the query again from the first page.

## Read a past block

`atBlock` reads the entities as they were at an earlier block:

```ts
const then = await publicClient
  .select({ $key: true, title: true })
  .from(Posts)
  .atBlock(1_000_000n)
  .fetch()
```

Nodes only keep a limited range of past blocks. A block outside that range fails with a `QueryError` whose `kind` is `"block"`.
