Every entity mutation goes through a standard Ethereum transaction. It uses `eth_sendRawTransaction`. Mutations include creates, patches, deletes, expiry extensions, ownership changes, and batches of these operations.

There is no dedicated `arkiv_*` write method. The node reads Arkiv operations out of a normal transaction, the same way it reads other contract calls.

<Aside type="caution">
Send every mutation transaction to a fixed address: `0x4400000000000000000000000000000000000044`. This is the precompile address for entity operations. It is the same on every Arkiv chain.

The calldata encoding for this address is internal to the SDK. It is not part of the published protocol. Do not build a raw transaction by hand. Use the wallet actions of the [TypeScript SDK](/typescript-sdk/mutating-data/). They build, sign, and send the transaction for you.
</Aside>

## Wallet actions

These methods come from `@arkiv-network/sdk`. Each one is a call on a `WalletArkivClient`, and each call sends exactly one `eth_sendRawTransaction`. Click a method name to open its API reference:

| Action | What it does |
|--------|--------------|
| [`createEntity()`](/typescript-sdk/api-reference/main/type-aliases/walletarkivactions/#createentity) | Creates a new entity with a payload, content type, attributes, and an expiry |
| [`patchEntity()`](/typescript-sdk/api-reference/main/type-aliases/walletarkivactions/#patchentity) | Sets or unsets individual attributes, or replaces the payload, leaving anything unnamed untouched |
| [`deleteEntity()`](/typescript-sdk/api-reference/main/type-aliases/walletarkivactions/#deleteentity) | Deletes an entity |
| [`extendEntity()`](/typescript-sdk/api-reference/main/type-aliases/walletarkivactions/#extendentity) | Moves an entity's expiry later |
| [`changeOwnership()`](/typescript-sdk/api-reference/main/type-aliases/walletarkivactions/#changeownership) | Transfers an entity to a new owner |
| [`executeBatch()`](/typescript-sdk/api-reference/main/type-aliases/walletarkivactions/#executebatch) | Applies a combination of creates, patches, deletes, extensions, and ownership changes atomically in one transaction |

See [Mutating Data](/typescript-sdk/mutating-data/) for usage examples of each.

## Confirming a mutation

`eth_sendRawTransaction` returns a transaction hash immediately. The network does not apply the mutation until a block includes the transaction.

```bash
curl https://rpc.tiramisu.db-chain.testnet.arkiv.network \
  -H "content-type: application/json" \
  -d '{
    "jsonrpc":"2.0",
    "id":1,
    "method":"eth_sendRawTransaction",
    "params":["'"$SIGNED_TX"'"]
  }'
```

Poll for the receipt to make sure that a block includes the transaction:

```bash
curl https://rpc.tiramisu.db-chain.testnet.arkiv.network \
  -H "content-type: application/json" \
  -d '{
    "jsonrpc":"2.0",
    "id":1,
    "method":"eth_getTransactionReceipt",
    "params":["'"$TX_HASH"'"]
  }'
```

The SDK's `waitForTransactionReceipt` (inherited from viem) does this polling for you.

## Watching for the result

Every mutation emits an entity-lifecycle event, decoded from the transaction's logs. There is no dedicated `arkiv_subscribe*` method. Watching these events rides on the standard `eth_getLogs` and `eth_subscribe` methods, the same way other contract events do.

The SDK wraps this in `watchEntityEvents()`, with handlers for each event type (`onEntityCreated`, `onEntityPatched`, `onExpiryExtended`, `onOwnershipTransferred`, `onEntityDeleted`) plus a catch-all `onEvent`. See [Live Events](/typescript-sdk/live-events/) for details.
