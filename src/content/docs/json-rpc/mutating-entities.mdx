All entity mutations, creates, patches, deletes, expiry extensions, ownership changes, and batches of any of these, are sent as standard Ethereum transactions via `eth_sendRawTransaction`. There's no dedicated `arkiv_*` write method: the node reads Arkiv operations out of a normal transaction the same way it reads any other contract call.

<Aside type="caution">
The target address of the transaction and its calldata encoding are internal to the SDK. They are not part of the published protocol. Do not build a raw transaction against them. Use the wallet actions of the [TypeScript SDK](/typescript-sdk/mutating-data/). They build, sign, and send the transaction for you.
</Aside>

## Wallet actions

Each of these is one call on a `WalletArkivClient`, and each sends exactly one `eth_sendRawTransaction`:

| Action | What it does |
|--------|--------------|
| `createEntity()` | Creates a new entity with a payload, content type, attributes, and an expiry |
| `patchEntity()` | Sets or unsets individual attributes, or replaces the payload, leaving anything unnamed untouched |
| `deleteEntity()` | Deletes an entity |
| `extendEntity()` | Moves an entity's expiry later |
| `changeOwnership()` | Transfers an entity to a new owner |
| `executeBatch()` | Applies any combination of creates, patches, deletes, extensions, and ownership changes atomically in one transaction |

See [Mutating Data](/typescript-sdk/mutating-data/) for usage examples of each.

## Confirming a mutation

`eth_sendRawTransaction` returns a transaction hash immediately. The mutation is not applied until a block includes the transaction.

```bash
curl https://rpc.cheesecake.db-chain.devnet.gobas.me \
  -H "content-type: application/json" \
  -d '{
    "jsonrpc":"2.0",
    "id":1,
    "method":"eth_sendRawTransaction",
    "params":["'"$SIGNED_TX"'"]
  }'
```

Poll for the receipt to make sure that a block includes the transaction:

```bash
curl https://rpc.cheesecake.db-chain.devnet.gobas.me \
  -H "content-type: application/json" \
  -d '{
    "jsonrpc":"2.0",
    "id":1,
    "method":"eth_getTransactionReceipt",
    "params":["'"$TX_HASH"'"]
  }'
```

The SDK's `waitForTransactionReceipt` (inherited from viem) does this polling for you.

## Watching for the result

Every mutation emits an entity-lifecycle event, decoded from the transaction's logs. There's no dedicated `arkiv_subscribe*` method: watching rides on the standard `eth_getLogs` and `eth_subscribe` methods, the same way any other contract event does.

The SDK wraps this in `watchEntityEvents()`, with handlers for each event type (`onEntityCreated`, `onEntityPatched`, `onExpiryExtended`, `onOwnershipTransferred`, `onEntityDeleted`) plus a catch-all `onEvent`. See [Live Events](/typescript-sdk/live-events/) for details.
