This page shows you how to read entities from Arkiv with the public client of the TypeScript SDK. The client gives you a chainable query builder with field selection, filtering, pagination, and payload retrieval.

## PublicClient Setup

All queries use the read-only public client:

```ts
import { createPublicClient } from "@arkiv-network/sdk"
import { tiramisu } from "@arkiv-network/sdk/chains"
import { http } from "viem"

const publicClient = createPublicClient({
  chain: tiramisu,
  transport: http(),
})
```

## Building Queries

Use `select()` to name the entity fields that you want, then chain filters and run the query with `.fetch()`:

```ts
import { eq, gt } from "@arkiv-network/sdk/query"

const result = await publicClient
  .select({ key: true, payload: true, attributes: true })
  .where(eq('type', 'note'), gt('created', Date.now() - 86400000))
  .limit(10)
  .fetch()

console.log('Found:', result.entities.length)
```

### Selecting Fields

Pass nothing, or `"*"`, to fetch every field. Pass an object to fetch only specific fields:

```ts
// All fields
await publicClient.select().where(eq('type', 'note')).fetch()

// Only the fields you need
await publicClient
  .select({ key: true, owner: true, payload: true })
  .where(eq('type', 'note'))
  .fetch()
```

Available fields: `key`, `owner`, `creator`, `createdAt`, `updatedAt`, `expiresAt`, `creationFlags`, `contentType`, `payload`, `attributeSchema`, `attributes`.

<Aside>
Select only what you need. The network sends every selected field, so an unused field makes the query slower. Each field is opt-in, including `key`.
</Aside>

The result type comes from your selection. The `toText()` and `toJson()` payload helpers work only when you select `payload`.

```ts
const [entity] = (await publicClient.select({ owner: true, payload: true }).fetch()).entities

entity.owner     // OK: Hex
entity.toJson()  // OK: payload was selected
entity.creator   // Compile error: not selected
```

<Aside type="caution">
Pass the selection inline. A selection stored in a variable widens its `true` values to `boolean`, so the result type loses its precision. To reuse a selection, annotate it `as const`:

```ts
const fields = { owner: true, payload: true } as const
await publicClient.select(fields).where(eq('type', 'note')).fetch()
```
</Aside>


### Query Builder Methods

| Method | Description |
|--------|-------------|
| `.where(...conditions)` | Add filter conditions (chainable) |
| `.ownedBy(address)` | Filter by current owner |
| `.createdBy(address)` | Filter by original creator (immutable) |
| `.limit(n)` | Limit number of results |
| `.fetch()` | Execute the query |

### Passing Multiple Conditions

You can chain `.where()` calls, pass several conditions as arguments, or pass an array. Every form combines the conditions with AND:

```ts
// Chained: each .where() adds an AND condition
const result = await publicClient
  .select({ key: true, payload: true })
  .where(eq('type', 'note'))
  .where(gt('priority', 3))
  .fetch()

// Varargs: same result as above
const result = await publicClient
  .select({ key: true, payload: true })
  .where(eq('type', 'note'), gt('priority', 3))
  .fetch()

// Array syntax: also the same result
const result = await publicClient
  .select({ key: true, payload: true })
  .where([eq('type', 'note'), gt('priority', 3)])
  .fetch()
```

## Query Operators

```ts
import { eq, gt, lt, gte, lte, startsWith, not } from "@arkiv-network/sdk/query"

eq('type', 'note')          // type = "note"
gt('priority', 3)           // priority > 3
lt('price', 1000)           // price < 1000
gte('created', timestamp)   // created >= timestamp
lte('expiration', limit)    // expiration <= limit
startsWith('title', 'RFC')  // title starts with "RFC"
```

<Aside type="caution" title="Three exported predicates do not work yet">
The SDK also exports `ne()`, `exists()` and `hasType()`. The node does not implement them at this version. A query that uses one of them fails to parse.

For a not-equal test, write `not(eq('type', 'archived'))` instead. This also matches entities that never set the attribute, because it is the full complement.
</Aside>

<Aside>
String attributes support `eq()` and `startsWith()`. Numeric attributes (`i32`, `u64`, `u256`, `dec`) support every comparison operator. Store numbers as numeric attributes to run range queries.
</Aside>

### Combining with and() / or()

Nest conditions with `and()` and `or()`. Both functions accept the predicates as separate arguments, or as a single array:

```ts
import { and, or, eq, gt } from "@arkiv-network/sdk/query"

// type = "note" AND (priority > 3 OR pinned = "true")
const result = await publicClient
  .select({ key: true, payload: true })
  .where(eq('type', 'note'), or(gt('priority', 3), eq('pinned', 'true')))
  .fetch()

// Array form works too: or([gt('priority', 3), eq('pinned', 'true')])
```

## Filtering by Owner and Creator

Every entity has two metadata fields:

- **`$owner`**: the wallet that currently owns the entity. It can change when the owner transfers the entity.
- **`$creator`**: the wallet that first created the entity. This field is immutable, so it never changes.

```ts
// Filter by current owner
const owned = await publicClient
  .select({ key: true, owner: true, payload: true })
  .where(eq('type', 'note'))
  .ownedBy('0xOwnerAddress')
  .fetch()

// Filter by original creator (tamper-evident)
const created = await publicClient
  .select({ key: true, creator: true, payload: true })
  .where(eq('type', 'note'))
  .createdBy('0xCreatorAddress')
  .fetch()
```

<Aside type="tip">
Use `.createdBy()` for a tamper-evident guarantee of who wrote the data, for example to make sure that data came from your trusted backend. The `$creator` field is immutable, so no one can spoof it after creation.
</Aside>

## Getting a Single Entity

Retrieve a specific entity by key:

```ts
const entity = await publicClient.getEntity(entityKey)

// Parse the payload
const data = entity.toJson()   // JSON payload
const text = entity.toText()   // Text payload
```

`getEntity()` always returns every field populated, so you do not need a selection.

## Reading Results

```ts
const result = await publicClient
  .select({ key: true, payload: true, attributes: true })
  .where(eq('type', 'note'))
  .fetch()

for (const entity of result.entities) {
  // Access payload (payload was selected)
  const data = entity.toJson()
  console.log(data.title, data.content)

  // Access entity key (key was selected)
  console.log('Key:', entity.key)

  // Access attributes (attributes were selected): an object keyed by name
  for (const [name, attribute] of Object.entries(entity.attributes)) {
    console.log(`${name}: ${attribute.value}`)
  }
}
```

## Pagination

Arkiv uses cursor-based pagination. A page holds at most 200 results.

```ts
let result = await publicClient
  .select({ key: true, payload: true })
  .where(eq('type', 'note'))
  .limit(10)
  .fetch()

console.log('Page 1:', result.entities.length)

// More pages: next() returns a new QueryResult, it does not change this one
if (result.hasNextPage()) {
  result = await result.next()
  console.log('Page 2:', result.entities.length)
}
```

## Sorting Results

The network always returns matching entities newest first. The server does not support any other order. To sort by an attribute, fetch the entities, then sort them in JavaScript:

```ts
const { entities } = await publicClient
  .select({ key: true, payload: true, attributes: true })
  .where(eq('type', 'note'))
  .fetch()

// Read the numeric "priority" attribute off an entity
const priorityOf = (entity: (typeof entities)[number]) =>
  Number(entity.attributes.priority?.value ?? 0)

// Highest priority first
entities.sort((a, b) => priorityOf(b) - priorityOf(a))
```

<Aside type="caution">
`.limit(n)` caps the results before your sort runs. As a result, you get the n newest matches, not the top n by your attribute. For a true top n, fetch all matching entities, paginate if needed, then sort and slice the results.
</Aside>

<Aside type="caution">
Older SDK versions had `orderBy()` and the `asc()` and `desc()` helpers. Version 0.8.0 removed them. Sort your results in JavaScript instead.
</Aside>

:::caution[String pattern matching]
The SDK supports prefix matching on string attributes with `startsWith("name", "prefix")`. The TypeScript SDK does not yet support full glob matching. For that, use the [JSON-RPC API](/json-rpc/querying-data/#query-syntax) directly.
:::
